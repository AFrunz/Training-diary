# 🏋️ Дневник тренировок

> Локальное Android-приложение для ведения силового дневника: что делал, с какими весами, насколько регулярно.
> Без аккаунтов, без сервера, без интернета. Все данные — на устройстве, с возможностью выгрузить и перенести.

**Версия документа:** 1.1 · **Статус:** согласовано · **Платформа:** Android (React Native)

---

## 1. Зачем это нужно

| Цель | Как измеряем, что получилось |
| --- | --- |
| Видеть **динамику весов** по каждому упражнению | С экрана упражнения за 2 тапа виден график и история подходов |
| Видеть **регулярность** и не обманывать себя | Календарь показывает месяц целиком; пропуск отличим от запланированного отдыха |
| Быстро вести журнал **прямо в зале** | Добавление подхода — не больше 3 тапов, экран не гаснет во время тренировки |
| Не потерять данные | Экспорт/импорт всей базы одним файлом |

**Пользователь:** один человек, сам себе тренер. Многопользовательского режима нет.

---

## 2. Словарь терминов

В исходной постановке слово «сет» означало и шаблон тренировки, и подход в упражнении. Разводим термины явно — дальше по документу и в коде используются только они:

| Термин | Что это | Пример |
| --- | --- | --- |
| **Упражнение** (`Exercise`) | Справочная единица: жим лёжа, тяга верхнего блока | «Приседания со штангой» |
| **Программа** (`Program`) | Именованный набор упражнений + цвет. Название произвольное — приложение не навязывает схему «Программа А / Программа Б» и ничего не подставляет само. Количество не ограничено: типично 2–4, но интерфейс обязан выдерживать больше | «Грудь + трицепс», «Спина + бицепс», «Ноги + пресс», цвет `#E45C5C` |
| **Тренировка** (`Workout`) | Проведение программы в конкретный день | Тренировка 11.08 по программе «Грудь + трицепс» |
| **Подход** (`Set`) | Одна рабочая серия: вес × повторения | 80 кг × 8 |
| **Отсутствие** (`Absence`) | Запланированный пропуск: отпуск, болезнь, командировка | 01.07 – 14.07, «отпуск» |

```

```

## 4. Функциональные требования

### 4.1 Календарь

- **FR-1.1.** Два режима: **месяц** (по умолчанию) и **год**. Переключатель в шапке, выбранный режим запоминается между запусками.
- **FR-1.2.** День с тренировкой помечается кружком **цвета программы**. Цвет задаётся при создании программы из фиксированной палитры (см. §7.3).
- **FR-1.3.** **В одном дне не более одной тренировки.** Попытка создать вторую тренировку на занятый день предлагает открыть существующую.
- **FR-1.4.** Дни, попадающие в период **отсутствия**, закрашиваются серым фоном. Отсутствие не считается пропуском в статистике регулярности.
- **FR-1.5.** Тап по дню открывает тренировку этого дня; если её нет — предлагает создать (программа предвыбрана — последняя использованная).
- **FR-1.6.** Долгий тап по дню / кнопка «＋» → создать отсутствие: диапазон дат, тип (отпуск / болезнь / травма / другое), заметка.
- **FR-1.7.** В годовом режиме — 12 компактных мини-месяцев с кружками цвета программы.
- **FR-1.8.** Текущий день визуально выделен всегда, в обоих режимах.

### 4.2 Библиотека упражнений

- **FR-2.1.** CRUD упражнения. Поля: **название** (обязательное, уникальное без учёта регистра), группа мышц (из списка), заметка.
- **FR-2.1.1.** Создание — отдельный экран с теми же полями. Название проверяется на дубликат **прямо при вводе**: совпадение показывается сразу, до попытки сохранить. Кнопка «Создать» неактивна, пока название пустое. Количество упражнений не ограничено.
- **FR-2.2.** Поиск по списку, сортировка: по алфавиту / по частоте использования / по дате последнего выполнения.
- **FR-2.3.** Упражнение, использованное хотя бы в одной тренировке, **нельзя удалить** — только архивировать: оно исчезает из выбора при составлении программ, но история сохраняется.
- **FR-2.4.** С карточки упражнения открывается **История** (см. §4.5).

### 4.3 Программы

- **FR-3.1.** CRUD программы. Поля: **название** — произвольная строка, которую пишет пользователь («Грудь + трицепс», «День А», «Тяжёлая»); поле пустое по умолчанию, никаких автоподстановок вроде «Программа 1». **Цвет** из палитры и список упражнений в заданном порядке (drag-and-drop).
  Программа — это тренировочный день, а не мышечная группа: обычно она объединяет несколько групп («Спина + плечи + трицепс»). В интерфейсе название программы и группа мышц упражнения не должны выглядеть однотипно, чтобы их не путали — примеры и плейсхолдеры показывают именно составные названия.
- **FR-3.1.1.** Создание — отдельный экран: пустое поле названия в фокусе, выбор цвета и пустой состав. Кнопка «Создать» неактивна, пока название пустое. По умолчанию предлагается первый цвет, не занятый другими программами.
- **FR-3.1.2.** Упражнения добавляются в программу через модальный **выбор из библиотеки**: поиск, группировка по мышцам, множественный выбор галочками. Оттуда же можно создать новое упражнение — черновик программы при этом не теряется.
- **FR-3.2.** Программа может быть **пустой** — без единого упражнения. Это штатный способ провести нестандартную тренировку: упражнения добавляются прямо в ней (FR-4.5).
- **FR-3.3.** Одно упражнение может входить в несколько программ. Внутри одной программы — не более одного раза.
- **FR-3.4.** Для упражнения в программе можно задать **план**: целевое число подходов и повторений (подсказка во время тренировки, на расчёты не влияет).
- **FR-3.5.** Изменение состава программы **не задевает уже проведённые тренировки** — состав копируется в тренировку в момент её создания (снапшот).
- **FR-3.6.** Программу можно дублировать («Грудь + трицепс» → «Грудь + трицепс (копия)») и архивировать по тем же правилам, что упражнения.
- **FR-3.7.** **Количество программ не ограничено.** Рабочий диапазон — 2–4 активные программы, но ни один экран не имеет права ломаться на большем числе. Правила масштабирования:
  - легенда календаря и фильтры в списке тренировок показывают все **неархивированные** программы; при нехватке ширины — горизонтальная прокрутка ряда, а не перенос и не обрезание;
  - в легенде и фильтрах программа обозначается точкой своего цвета и коротким именем; если имя длиннее 14 символов, оно усекается многоточием;
  - распределение по программам в статистике строится на **N сегментов**, а не на два; программы с нулём тренировок за период в диаграмму не попадают, но остаются в списке ниже;
  - при 5+ программах легенда календаря сворачивается в строку «Программы: 6» с раскрытием по тапу.

### 4.4 Тренировка

- **FR-4.1.** Создание: дата (по умолчанию **сегодня**) + программа, программа обязательна. Момент создания фиксируется как `startedAt`.
- **FR-4.2.** Экран тренировки — список упражнений программы. У каждого: чекбокс «выполнено», подходы, кнопка «＋ подход», кнопка «История».
- **FR-4.3.** **Счётчик времени** в шапке экрана тренировки: сколько прошло с `startedAt`, формат `1 ч 12 мин` (до часа — `12 мин`). Обновляется раз в минуту, тикает, пока тренировка не завершена. После завершения на его месте — итоговая длительность.
- **FR-4.4.** Добавление подхода: **вес** и **повторы**. Вес можно оставить пустым — для турника, отжиманий и подобного; такой подход отображается как `× 12`. Оба поля предзаполняются значениями предыдущего подхода этого же упражнения (в этой тренировке, иначе — из прошлой тренировки). Подход можно отредактировать и удалить свайпом.
- **FR-4.5.** Отметка «выполнено» зачёркивает строку упражнения и сохраняет **временную метку** отметки — она участвует в расчёте длительности (см. §5.1). Снятие отметки метку удаляет.
- **FR-4.6.** В тренировку можно **добавить упражнение вне программы** (разовое отклонение) и **пропустить** любое из программы — пропущенное просто остаётся неотмеченным.
- **FR-4.7.** Тренировку можно редактировать задним числом — включая **время начала и окончания** — и удалять (с подтверждением).
- **FR-4.8.** Список тренировок: карточки, отсортированные по дате убыв. На карточке — дата, программа (цветовая метка), длительность и **бублик прогресса** (см. §5.2).
- **FR-4.9.** Во время активной тренировки экран не гаснет; в списке активная тренировка закреплена сверху с бейджем «Идёт · 1 ч 12 мин».

### 4.5 История упражнения

- **FR-5.1.** Открывается по кнопке — из экрана тренировки и из карточки упражнения. Не раскрыта по умолчанию.
- **FR-5.2.** Содержит: **график** рабочего веса по датам (переключатель: макс. вес / оценочный 1ПМ) и **список** тренировок с полной раскладкой подходов.
- **FR-5.3.** Рекорды подсвечиваются: максимальный вес и максимум повторений.
- **FR-5.4.** Из истории видно дельту к предыдущему разу: `82.5 кг (+2.5)`.

### 4.6 Статистика

- **FR-6.1.** Периоды: **по годам** и **по месяцам**, с переключателем и свайпом между периодами.
- **FR-6.2.** Показатели: среднее число тренировок в неделю и в месяц; всего тренировок; средняя длительность; **процент завершённости**; текущая и рекордная серия недель без пропуска; распределение тренировок по программам; дней отсутствия.
- **FR-6.3.** График «тренировок по неделям» за выбранный период.
- **FR-6.4.** Показатели, для которых не хватает данных, показываются как «—», а не как 0.

### 4.7 Данные и настройки

- **FR-7.1.** **Экспорт**: вся база в один `.json`-файл (схема версионирована) через системный share-sheet или в папку загрузок. Имя: `training-diary-YYYY-MM-DD.json`.
- **FR-7.2.** **Импорт**: выбор файла, предпросмотр (что и в каком количестве приедет), режим **«Заменить всё»** или **«Дополнить»** (по `id`, конфликт — берём более свежий `updatedAt`).
- **FR-7.3.** Автоматический локальный бэкап при каждом запуске, хранится 5 последних копий, восстановление из настроек.
- **FR-7.4.** Настройки: **единицы веса — килограммы (по умолчанию) или фунты**, первый день недели, **язык (системный / русский / английский)**, тема (системная / светлая / тёмная), удалить все данные.
- **FR-7.6.** Смена языка применяется **сразу, без перезапуска**, и не трогает пользовательские данные: названия программ, упражнений и заметки остаются как их ввели. Переводятся только строки интерфейса, названия месяцев и дней недели. По умолчанию берётся язык системы, при неподдерживаемом — английский.
- **FR-7.5.** Единица веса — глобальная. При переключении **исторические значения не пересчитываются и не переписываются**: вес хранится в килограммах, отображается в выбранных единицах с округлением до 0.5 кг / 1 lb.

## 5. Правила расчётов

Самая спорная часть исходного ТЗ — здесь она зафиксирована однозначно.

### 5.1 Длительность тренировки

```
startedAt  = момент создания записи о тренировке
finishedAt = временная метка последнего отмеченного упражнения
duration   = finishedAt − startedAt
```

Уточнения, без которых формула ломается:

- Если **не отмечено ни одного** упражнения → `duration = null`, показываем «—», в средние значения не входит.
- Если тренировка создана **не на сегодня** (задним числом) → `startedAt` считается недостоверным, `duration = null`.
- По завершении тренировки **время начала и окончания можно поправить вручную** (FR-4.7). Ручные значения приоритетнее вычисленных, факт правки отмечается иконкой.
- Длительность > 6 часов помечается как выброс и **исключается из средних** (скорее всего забыли отметить упражнение).

### 5.2 Завершённость («бублик»)

```
completion = отмеченных упражнений / всего упражнений в тренировке
```

| Значение | Цвет | Токен |
| --- | --- | --- |
| 100 % | 🟢 зелёный | `success` |
| 50 – 99 % | 🟠 оранжевый | `warning` |
| < 50 % | 🔴 красный | `danger` |
| 0 % и нет подходов | ⚪️ серый, «не начата» | `muted` |

Разово добавленные упражнения (FR-4.6) входят в знаменатель.

### 5.3 Прочие метрики

- **Оценочный 1ПМ** (Эпли): `вес × (1 + повторы / 30)`, показывается при `повторы ≤ 12` и заполненном весе.
- **Тренировок в неделю** = число тренировок / число недель периода, где **недели, полностью попавшие в отсутствие, из знаменателя исключаются**.
- **Серия (streak)** = количество подряд идущих недель, в каждой из которых была хотя бы одна тренировка; недели отсутствия серию не прерывают.
- Все даты трактуются в **локальной таймзоне устройства**; принадлежность тренировки дню определяется по локальной календарной дате, а не по UTC.

## 6. Модель данных

```ts
Exercise   { id, name, muscleGroup?, note?, archivedAt?, createdAt, updatedAt }

Program    { id, name, color, archivedAt?, createdAt, updatedAt }
ProgramItem{ id, programId, exerciseId, order, targetSets?, targetReps? }

Workout    { id, date /* UNIQUE */, programId, programName, programColor,  // снапшот
             startedAt, finishedAt?, manualStartedAt?, manualFinishedAt?,
             note?, createdAt, updatedAt }
WorkoutItem{ id, workoutId, exerciseId, exerciseName, order,
             isAdHoc: bool, completedAt? }
WorkoutSet { id, workoutItemId, order, weightKg?, reps, createdAt }

Absence    { id, startDate, endDate, type, note? }
Settings   { unit: 'kg'|'lb', firstDayOfWeek, theme, schemaVersion }
```

Правила: `id` — UUID (чтобы импорт из разных копий не конфликтовал); `Workout.date` — уникальный индекс, гарантирующий одну тренировку в день; удаление — мягкое, через `archivedAt`; вес всегда хранится в килограммах; `programName` / `exerciseName` дублируются в записях тренировки, чтобы история не «поехала» после переименования.

## 7. Нефункциональные требования

### 7.1 Технические

- **Полностью офлайн.** Приложение не запрашивает разрешение на интернет.
- Данные — в локальной **SQLite**; база лежит в приватной директории приложения.
- Холодный старт ≤ 2 с, открытие календаря ≤ 300 мс на объёме **5 лет × 4 тренировки в неделю** (~1000 тренировок, ~20 000 подходов).
- Приложение переживает убийство процесса в фоне без потери введённых подходов (запись в БД сразу, не по кнопке «Сохранить»).

### 7.2 UX

- Ввод веса и повторов — **числовая клавиатура**, шаг кнопками ±2.5 кг (±5 lb) и ±1 повтор, без обязательного набора с клавиатуры.
- Всё удаляемое удаляется с `Undo`-снекбаром.
- Тёмная тема обязательна: в зале ей пользуются чаще светлой.
- Языки интерфейса — русский и английский, переключаются в настройках (FR-7.4). Захардкоженных строк в компонентах нет, всё через словарь.
- Числительные склоняются по правилам языка: «1 тренировка», «3 тренировки», «11 тренировок». Отдельная функция плюрализации, а не конкатенация строк.

### 7.3 Палитра программ

Фиксированный набор из 8 цветов, различимых на глаз и при дальтонизме, с контрастом ≥ 3:1 к фону в обеих темах. Свободный color-picker не даём: он ломает читаемость календаря. Восьми цветов хватает на типичные 2–4 программы с запасом; при создании новой программы первым предлагается ещё не занятый цвет, а если заняты все восемь — цвета начинают повторяться, и это допустимо.

---

### 7.4 Иконка и графика

- **Иконка приложения** — Android adaptive icon: фоновый слой сплошного цвета `#5A5AF0` и передний слой с белым знаком гантели 72 dp, полностью укладывающимся в безопасную зону 66 dp. Знак собран из крупных скруглённых плашек без тонких линий, поэтому читается и на 48 px. Дополнительно нужны **монохромный слой** для тем оформления Android 13+ и квадратная плитка **512 × 512** для Google Play. Текста на иконке нет.
- **Экран запуска** — системный splash Android 12+: фон по теме, иконка по центру, подпись с названием внизу. Своей анимации и картинок не рисуем.
- **Интерфейсные иконки** — набор [lucide](https://lucide.dev), обводка 2 px, размеры: 22 — таббар, 18–19 — шапки и строки списков, 16 — кнопки, 14–15 — подписи. Используется 27 иконок; полный перечень с назначением каждой — на отдельном фрейме в макете, чтобы в сборку попали только нужные.
- Иллюстраций, маскотов и фотографий в приложении нет: пустые состояния оформляются иконкой и текстом.

## 11. Критерии приёмки

1. Создаю упражнения, собираю из них две программы разных цветов — обе видны в календаре разными кружками.
2. Создаю тренировку на сегодня — в шапке идёт счётчик времени с момента создания.
3. Добавляю подходы (в том числе подход без веса — подтягивания), отмечаю 3 упражнения из 5 — на карточке оранжевый бублик «3/5» и длительность от создания до последней отметки.
4. Отмечаю все — бублик зелёный, 100 %.
5. Пытаюсь создать вторую тренировку на тот же день — приложение открывает существующую.
6. Правлю время начала завершённой тренировки — длительность и средние в статистике пересчитываются.
7. Ставлю отпуск на две недели — дни серые, а средние по регулярности за месяц из-за него не проседают.
8. В истории жима видны все подходы за всё время и график роста веса.
9. Переключаю единицы на фунты — вся история отображается в фунтах, при возврате в кг значения совпадают с исходными.
10. Экспортирую файл, стираю данные, импортирую обратно — состояние совпадает полностью, включая длительности.
11. Убиваю приложение посреди тренировки — все введённые подходы на месте.

## 12. Зафиксированные решения

| Вопрос | Решение |
| --- | --- |
| Несколько тренировок в один день | **Нет**, одна тренировка на дату (уникальный индекс в БД) |
| Тренировка без программы | **Нет**, программа обязательна; для нестандартной тренировки создаётся пустая программа |
| Что считать началом тренировки | Момент создания записи; по завершении время правится вручную |
| Упражнения без веса (турник, планка) | Отдельного типа упражнений нет — в подходе просто **не заполняется вес** |
| Тоннаж и объём нагрузки | **Не считаем** — упрощаем модель и статистику |
| Единицы измерения | Кг по умолчанию + **поддержка фунтов**, хранение всегда в кг |
| Переносимость данных | Достаточно **ручного экспорта в файл** + автобэкапы |
| Таймер отдыха между подходами | **Не нужен** |
| Время с начала тренировки | Живой счётчик в шапке экрана тренировки и бейдж «Идёт» в списке |
| Сколько может быть программ | Сколько угодно; проектируем на 2–4, но легенда, фильтры и статистика масштабируются на N (FR-3.7) |
