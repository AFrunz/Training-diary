# 📦 Сборка и выпуск

## Что делает CI

| Workflow | Когда | Что делает |
| --- | --- | --- |
| `.github/workflows/tests.yml` | пуш в `main`, пул-реквест, вручную | типы, 714 тестов, сборка бандла |
| `.github/workflows/deps.yml` | по понедельникам, вручную | `expo-doctor`: версии пакетов под SDK |
| `.github/workflows/release.yml` | публикация релиза, вручную | типы, тесты плюс APK: кладёт в артефакты и прикладывает к релизу |

Сборка бандла в проверках стоит не для красоты: она ловит ошибки импортов и конфигурации сборщика, которых не видят тесты. Именно так однажды выяснилось, что Expo Router принимал за папку маршрутов слой сценариев.

### Почему `expo-doctor` вынесен в отдельный прогон

Он сверяет версии пакетов со списком, который живёт **в реестре Expo, а не в
репозитории**. Стоит Expo выпустить патчи SDK — и проверка краснеет на коммите,
который ничего не менял. Дважды подряд это роняло сборку на ровном месте,
поэтому в гейте на каждый пуш ей не место: она про окружение, а не про
изменение. Раз в неделю — то что нужно.

Когда еженедельный прогон покраснел, догнать версии:

```sh
npx expo install --fix
```

Если команда падает на конфликте зависимостей — `@react-native/jest-preset`
обязан совпадать по версии с `react-native`, а `expo install` его не трогает.
Тогда доставить обе руками и перепроверить:

```sh
npm install react-native@<нужная> -D @react-native/jest-preset@<та же>
npx expo-doctor@latest
```

Держать версии в тон SDK не педантизм: рассинхрон `react-native` однажды уже
ломал нативную сборку ошибкой `tryGetMutableBuffer` — на бандле и тестах это
никак не проявлялось.

### Версии GitHub Actions

Все действия в workflow должны работать на **Node 24**: GitHub принудительно
запускает на нём и те, что собраны под Node 20, и старые от этого падают. Так
однажды встала сборка релиза — на шаге `android-actions/setup-android@v3`,
хотя типы и тесты прошли. Если в логе видно предупреждение «Node.js 20 is
deprecated… being forced to run on Node.js 24», поднимите названные действия.
Проверить, на чём собрано действие, можно не заглядывая в CI:

```sh
curl -s https://raw.githubusercontent.com/<owner>/<repo>/<tag>/action.yml | grep using:
```

## Как выпустить версию

Всё делается из панели GitHub, править файлы заранее не нужно.

1. **Releases → Draft a new release**, тег вида `v1.0.1` (сборка сама уберёт `v`).
2. Описать изменения и нажать **Publish release**.
3. Через ~10 минут APK появится файлом в самом релизе и в артефактах вкладки Actions.

Версия приложения берётся из тега, а номер сборки — из счётчика запусков, поэтому
он всегда растёт: Google Play не принимает повторный. Значение `expo.version`
в `app.json` при этом не трогается — оно нужно только для локальных сборок.

Собрать без релиза: вкладка **Actions → Сборка APK → Run workflow**. Файл останется в артефактах на 90 дней.

## Подпись

Без секретов APK подписывается **отладочным ключом**. Такой файл ставится на телефон и годится для проверки, но Google Play его не примет, и обновить им ранее установленное приложение нельзя.

Для настоящей подписи создайте ключ:

```sh
keytool -genkeypair -v -keystore release.keystore -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -i release.keystore | pbcopy
```

И заведите четыре секрета в **Settings → Secrets and variables → Actions**:

| Секрет | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | содержимое буфера после команды выше |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | пароль ключа |

Ключ подкладывается скриптом `scripts/prepare-release-signing.mjs`: папка `android/` в репозитории не хранится, её каждый раз генерирует `expo prebuild`, а шаблон Expo подписывает релиз отладочным ключом.

**Файл `release.keystore` храните отдельно и не теряйте.** Приложение, подписанное другим ключом, Google Play не примет как обновление того же самого — придётся публиковать заново под новым именем пакета.

## Сборка вручную

```sh
npx eas-cli build -p android --profile preview      # APK через облако Expo
npx eas-cli build -p android --profile production   # app-bundle для Google Play
npx expo run:android --variant release              # локально, нужен Android SDK
```

## Перед публикацией в Google Play

- проверить APK из профиля `preview` на живом телефоне: в релизной сборке включается минификация, и иногда всплывает то, чего нет в разработке;
- иконка магазина 512 × 512 — уменьшенная `assets/icon.png`;
- скриншоты минимум с двух экранов;
- форма Data Safety: приложение не собирает данные и не имеет доступа в сеть — разрешение `INTERNET` удалено из манифеста;
- политика конфиденциальности: обязательна даже для офлайнового приложения.
